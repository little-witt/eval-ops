# FORGE Desktop V2 — 可追溯的 Skill 进化工作台

> 状态：任务详情结构与第二版视觉基线已确认，并已实现到 `desktop/` 产品客户端。同目录 HTML 仍是设计原型，实际产品由 Electron Renderer、主进程和内置 Kernel 驱动。

## 1. 本轮设计结论

V1 的问题不是缺少信息，而是信息组织错了：大盘先出现、任务因果链后出现，用户需要自己拼接 EvalPack、Case、执行路径、会话、日志、分析结论和优化动作之间的关系。

V2 把单任务详情定义为产品主场，并使用一条实时生长、可回放、可追溯的「进化轨迹」承载完整闭环：

```text
任务输入
  → EvalPack 生成/复用
  → Case + 执行路径流式生成
  → 线上会话批量执行
  → 日志完整回收
  → 本地 Agent 汇总诊断
  → 用户确认优化范围
  → 多文件候选变更
  → 回归策略路由
       ├─ 直接重新评测
       └─ 需求变化 / 覆盖不足 → 回到 Case 生成
```

任务中心和路径大盘保留，但只做跨任务摘要；用户创建任务后立即进入任务详情，不再停留在列表页。

## 2. 设计原则

1. **当前动作只有一个视觉焦点**：页面始终明确「系统此刻在做什么、为什么做、预计产出什么」。
2. **产出物不是日志附件**：EvalPack、Case、路径、日志、诊断、补丁都是一级对象，可以选择、比较、追溯和导出。
3. **一切结论可回证据**：评分维度和优化建议必须能下钻到 Case、执行路径和对应会话日志。
4. **轮次是不可变快照**：每轮保留输入版本、EvalPack 版本、Case 集、Skill commit、环境、会话、日志、判定、建议和候选 diff。
5. **只在高风险点打断用户**：系统自动完成生成和执行；只有目标/范围变更、冲突、候选修改和发布需要确认。
6. **低 Token 是可见预算**：展示本轮预算、复用节省量和增量上下文，不把技术计数放在用户主路径上。

## 3. 信息架构

### 3.1 桌面壳层

- **任务**：任务中心、筛选、需要操作、最近任务。
- **资源**：Skill、代码仓库、EvalPack 模板、验证环境。
- **运行记录**：跨任务会话、错误、Token 和耗时。
- **设置**：本地分析模型、CATX、Git 凭证、浏览器/验证环境、密钥管理。

### 3.2 任务详情

任务详情包含四层，视觉优先级从上至下：

1. **任务抬头**：目标、当前状态、轮次、Skill/代码版本、预算、暂停/终止。
2. **实时路径大盘**：六个主阶段的完成度、当前活动、阻塞和核心指标，随事件流实时更新。
3. **进化轨迹**：按真实事件顺序增长的节点流，是页面主体。
4. **证据检查器**：选中任意节点后显示其完整产出、来源、关联对象和历史版本。

## 4. 任务创建后的即时体验

用户点击「创建并开始」后：

1. 立即导航到新任务详情，生成稳定 task id。
2. 页面先显示输入快照和环境预检；不等待全部请求结束才展示页面。
3. EvalPack 节点进入流式生成状态，实时展示：来源识别、复用判断、目标维度、评分规则、质量门。
4. EvalPack 质量门通过后，Case/路径节点开始增长；用户输入 Case 标记为 `USER`，系统补充标记为 `GENERATED`。
5. 每个 Case 卡片生成完成后即出现，其路径步骤逐个展开；不要求全量 Case 完成后才可查看。
6. 所有必要 Oracle 和环境契约就绪后自动创建批量会话。

## 5. 进化轨迹节点

### 5.1 输入节点

- Skill 仓库 / branch / commit
- 代码仓库 / fixture / PR 范围
- 用户目标、标准、Case、非目标
- 任务模式：修复 / 优化 / 扩展 / 创建 / 探索

### 5.2 EvalPack 节点

直观呈现四类输出：

- **目标维度**：目标达成、执行路径遵循、结果质量、风险与边界。
- **评分规则**：每个维度的通过条件和权重。
- **资产复用**：复用了什么、为何可复用、新生成了什么。
- **质量门**：完整性、可执行性、Oracle 可信度和定义冻结。

EvalPack 仍然是系统内部评测资产，但 UI 不要求用户理解目录结构；高级入口允许查看/编辑 manifest、scenario 和 oracle。

### 5.3 Case 与路径节点

每个 Case 作为独立测试单元显示：

- 目标、来源、优先级、覆盖维度、输入摘要、预期结果。
- 执行路径：准备 → 调用 Skill → 关键步骤 → 产物/工具 → 判定。
- 路径契约：必经步骤、禁止动作、关键工具、预期证据。
- 生成依据：来自哪个用户标准或 Skill 步骤。

Case 卡片可以在图谱视图、矩阵视图和列表视图切换；默认图谱视图强调从维度到 Case、再到路径的映射。

### 5.4 在线评测节点

- 按 Case 批量创建 CATX 会话。
- 每个执行单元由 `case_revision × candidate/run_context × attempt` 唯一标识并映射一个 session；同一 Case 可有多次运行，任何重试都不覆盖旧记录。
- 每张运行卡显示：会话状态、最近事件、耗时、Token、日志完整度、路径执行进度。
- 用户点击路径步骤，可直接跳到对应 SSE 事件区间。
- 轮询状态、SSE 内容和最终完整日志三者分别记录，断线后可恢复。

### 5.5 汇总诊断节点

本地 Agent 读取结构化结果和必要日志片段，输出：

- 稳定通过、偶现、失败和基础设施错误分类。
- 问题簇，而不是孤立 Case 列表。
- 每个问题簇的证据：失败 Case、违背的路径、日志时间点、受影响维度。
- 优化建议：原因、改动策略、文件范围、收益覆盖、冲突/回归风险。
- 明确的下一步路由建议：重评 / 补 Case / 停止收敛。

### 5.6 用户决策节点

默认选中系统推荐的兼容修改集合。用户可以：

- 通过并执行；
- 取消某个建议；
- 补充意见或约束；
- 要求重新分析；
- 终止本轮。

用户补充若改变目标或暴露覆盖缺口，系统回到 Case 生成；仅影响实现策略则直接进入优化。

### 5.7 候选优化与回归路由

- 展示多文件 diff：`SKILL.md`、`scripts/`、`references/`、模板和测试资源均可修改。
- 每一处 diff 必须关联到建议和问题簇。
- 静态检查、本地验证、敏感信息检查和范围检查通过后生成候选 commit。
- 路由器基于目标变化、EvalPack 变化、覆盖变化和风险选择：
  - `rerun_same_cases`：同一冻结 Case 集重新评测，可比较前后差异。
  - `regenerate_cases`：新增目标、标准或覆盖缺口时，生成新 EvalPack 版本/Case 版本后再评测。
  - `converged`：收益收敛且门槛通过，进入最终确认。

## 6. 完整追溯模型

每个用户可见对象都有稳定 id 和版本：

| 对象 | 核心关联 |
|---|---|
| `task_revision` | 用户输入、配置和约束快照 |
| `round` | skill commit、evalpack revision、environment snapshot |
| `eval_dimension` | 用户标准 / Skill 内容来源 |
| `case_revision` | dimension、oracle、execution path |
| `path_step` | expected evidence、actual event range |
| `session_attempt` | case revision、CATX session id、poll/SSE status |
| `session_log` | raw event stream、normalized events、completeness |
| `verdict` | grader version、dimension scores、evidence refs |
| `issue_cluster` | verdicts、path violations、log refs |
| `proposal` | issue cluster、target files、risk、expected gain |
| `candidate` | proposal ids、diff、validation、commit |
| `route_decision` | evidence snapshot、reason、next phase |

事件流只追加，派生视图可重建。任何卡片都能打开「来源」并回到上游对象。

## 7. 实时路径大盘

大盘位于任务抬头下方，展示六个阶段：设计、生成、评测、诊断、优化、回归。

- 完成阶段：显示产出数量和质量门结果。
- 当前阶段：显示实时动作和细粒度进度。
- 待开始阶段：显示进入条件，而不是伪造百分比。
- 阻塞阶段：显示阻塞来源和可恢复动作。

大盘点击后滚动并聚焦相应轨迹节点。它是导航和摘要，不替代详细路径。

## 8. 视觉方向

### Precision Atelier / 精密工坊

- 深墨色桌面壳层承载长时运行的稳定感，象牙白工作面用于阅读重要产出。
- 钴蓝表示系统正在推导，朱砂橙表示需要用户决策，苔绿表示证据可信且通过。
- 用一条「活的轨迹线」串联所有节点；流式生成时轨迹线有克制的脉冲，不做装饰性炫光。
- 标题使用编辑型衬线字体，数据和事件使用窄体等宽字体，正文使用人文无衬线字体。
- 卡片通过层级、留白和细线组织，不采用同质化卡片瀑布流。

## 9. 正式实现分期（设计确认后）

### P0-A：可用闭环

- 桌面壳、任务创建、任务详情和进化轨迹。
- Kernel 事件适配为稳定 UI 事件协议。
- EvalPack/Case/Path/Session/Log/Diagnosis/Candidate 追溯存储。
- 自动进入详情、暂停/恢复/取消、断点续跑。
- 用户建议确认、补充意见和两类回归路由。

### P0-B：可靠线上闭环

- CATX 批量并发、限流、幂等建会话和可恢复采集。
- 日志完整性判定、缺失补抓、attempt 保留。
- 本地分析 Agent 结构化输出和低 Token 上下文裁剪。
- Git worktree 隔离、多文件候选、校验、提交和失败回滚。

### P0-C：真正好用

- 任务模板、仓库和环境复用。
- Case/路径图谱、证据跳转、轮次对比和导出。
- Keychain 密钥管理、预检诊断、空状态/错误恢复。
- 可访问性、键盘导航、长日志虚拟列表和性能验收。

### P1：D2C 与更多验证环境

- 本地浏览器验证适配器、视觉基线、差异图。
- 执行环境与验证环境的 Git commit 交接。
- 远程/云验证环境契约，不与任务核心耦合。

## 10. 已确认的产品决策

1. 「任务详情 + 进化轨迹」是产品主场，路径大盘作为摘要和导航保留。
2. 创建任务后自动运行到第一个人工决策点。
3. 右侧证据检查器统一承载 EvalPack、Case、路径、日志、建议和 diff 详情。
4. 回归路由由系统推荐；用户只能在控制器给出的安全路由集合内覆盖，不能绕过硬门、比较基线或 Holdout 规则。
5. 客户端结构和第二版视觉作为实现基线，完成真实客户端后再逐步打磨样式。

## 11. 自迭代 Kernel V2 在任务详情中的呈现

客户端结构与视觉继续以本 V2 方案为准。自迭代核的可信性规则、Case 生成标准、Trial 评测维度、跨 Case 诊断和收敛机制以 [Skill 评测与自迭代 Kernel V2](../../docs/current/EVALUATION_SELF_ITERATION_KERNEL_V2.md) 为准，任务详情必须增加以下产品表达：

1. **Eval 设计依据**：展示用户标准 / Skill 能力 → 测试义务 → Case 的映射，以及 Case 来源、家族、风险、Oracle 可信度和 `Draft → Executable → Calibrated → Frozen → Regression` 状态；失效或编辑时 fork 新 revision。
2. **预期路径与实际 Trace 叠加**：required、alternative、forbidden、recommended 检查点和局部顺序与 Session Log 证据一一对应。
3. **分层判定**：证据有效性是前置门；单 Attempt 展示 Outcome、过程、工具、产物、安全、恢复、表达和效率，Case Aggregate 展示可靠性，Candidate Comparison 展示增量价值与回归，硬事实不可被模型分数覆盖。
4. **分层诊断**：问题簇同时展示确定性事实、模型推断、人工确认、失败归因、冲突和精确修改范围。
5. **Champion / Challenger 收敛面板**：展示候选树、paired delta、关键回归、pass^k、预算、Holdout 与继续/晋升/拒绝/停止原因。
6. **Eval Health**：独立展示 Case、Oracle、Fixture、Grader 和日志健康度，防止把评测故障误判为 Skill 退化。

用户应能在任务详情中直接回答四个问题：为什么测这些、每条路径如何判、为什么提出这些修改、为什么系统选择继续或停止。页面不得只显示一个总分或一段模型总结。
